## 文件与口径

- `products.jsonl`：商品事实、稳定型号及配置ID、逐字段来源、可选规范规格。
- `reviews.jsonl`：107条适用关联，对应69个独立体验要点；区分原创评测、平台评价、用户帖子。
- `sources.jsonl`：902条来源的链接、采集时间、正文哈希和证据定位；HTTP响应与浏览工具正文快照分别标注。
- `manifest.json`：哈希、计数、批次、价格口径和能力状态。
- `release_policy.json`：型号规模、品类均衡与品牌分布门禁配置。

数据采用`source-preferred-v1`口径：已有厂商资料优先，其余选一个可读取的公开商品参数来源。319条配置价格来自官网、官方商城或已读取的销售页；230条来自中关村在线目录绑定配置的商家报价，明确标为“目录收录报价”，未逐件实时核价或核实商家经营主体。价格均为人民币快照，不保证库存或成交价，不采用个人资格补贴及以旧换新价。旧记录保留原采集时间；渠道及体验站点集中度作为诊断。

缺失规格、评分、销量和无法确认的日期保持未知；未知值不能满足硬条件，也不能解释为“不支持”。七类分别有16、27、50、29、43、65、57条配置存在决策规格缺项。已录规格保留条件，不把USB-C充电当作有线数据连接，或把面板刷新率当作各接口上限。

体验要点含26条原创评测、41条平台评价、2条用户帖子。七类型号覆盖率依次为10.67%、6.67%、5.71%、5.71%、0%、1.43%、4.29%，未达80%的正式支持门槛。未用宣传语补写体验。

来源原文缓存不随仓库分发，初始化只读取随仓库提供的JSONL。

## 初始化与维护

```bash
python -m src.data.prepare_catalog --validate-only
python -m src.data.prepare_catalog
python -m backend.bootstrap
```

导入不调用模型API，也不加载嵌入模型；构建索引使用配置中的嵌入模型。已有双库不覆盖、不合并，自定义路径须显式导入。迁移及启动方法见[开发说明](../../DEVELOPMENT.md)。访客无需访问来源网站。

```bash
python scripts/audit_catalog_quality.py --release-check
python -m evals.retrieval_runner
python -m evals.catalog_smoke
```

直接更新本目录，保留已有稳定ID和来源，重新核对清单哈希、计数、指纹及`evals/datasets/catalog/`中的76条独立标注。标注依据商品事实，不能用检索结果生成；精确配置和体验适用ID须独立复核。数据变化后先在新位置准备双库与索引再切换配置；目录、标注或索引不一致时评测报告`blocked`。来源缓存的完整核验可加`--source-cache data/source_cache`，运行报告留在`evals/results/`。

## 能力限制

容量、屏幕上限和明确显卡类型支持依据已有规格保守筛选；最高支持容量、可选配置、混合或未确认的显卡类型保持未知。其余自然语言规格尚未全部转成强制过滤。

受控模型冒烟只验证流程，不能代替真实模型的回答质量。全品类真实多轮对话尚未完成正式验收，七类继续标为试点。
